An identity is an account: one row with your profile fields, the provider logins linked to it, and whether its address was proven. `auth.identities` reads and writes it.

## The row

| Field | Meaning |
| --- | --- |
| `id` | Generated by the store. |
| `profile` | Your fields. `email` and `username` are required and unique; everything else is yours. |
| `providers` | Linked logins, each `{ providerId, providerSub, tenantId, addedAt, addedBy }`, such as `oauth:google` and Google's `sub`. A link signs in only to its own tenant. |
| `emailVerified` | Whether the address was proven by a link or a verified IdP, not merely typed. |
| `version` | Optimistic-concurrency counter; `updateProfile` takes it and refuses a stale write. |
| `deletedAt` | Set by a soft delete; the row reads as absent while it is set. |
| `createdBy`, `updatedBy`, `deletedBy` | The actor each write was attributed to, or `null`. |

## Typing the profile

The profile type flows from the engine's first type parameter:

```ts
import { MemoryAdapter } from '@gentleduck/auth/adapters/memory'
import { createAuth } from '@gentleduck/auth/core'

type Profile = { email: string; username: string; name: string; locale?: string }

const auth = createAuth<Profile>({
  baseUrl: 'http://localhost:3000',
  stores: new MemoryAdapter<Profile>(),
})

const ada = await auth.identities.create({ profile: { email: 'ada@example.com', username: 'ada', name: 'Ada' } })
ada.profile.name // string
```

The serialized profile is capped at 16 KiB by default; set `identities: { profileMaxBytes }` to change it, or `0` to remove the cap.

## Reading

```ts
await auth.identities.getById(id)
await auth.identities.getByEmail('ada@example.com').orNull()
await auth.identities.getByProviderSub('oauth:github', '583231').orNull()
```

Each answers an `Answer`: awaiting it throws `AUTH_IDENTITY_NOT_FOUND` for a missing or soft-deleted row, and `.orNull()` answers `null` instead. An id the database cannot hold, such as one that is not a uuid on Postgres, is refused with `AUTH_INVALID_PARAMETERS`, which `.orNull()` does not turn into `null`. Email lookups are case-insensitive, and take any address `create` stores, up to 320 characters. `getByProviderSub` finds the link in the tenant its third argument names, `{}` by default for a link with no tenant.

## Writing

```ts
const ada = await auth.identities.create({
  profile: { email: 'ada@example.com', username: 'ada', name: 'Ada' },
  emailVerified: false,
})

await auth.identities.updateProfile(ada.id, { name: 'Ada Lovelace' }, ada.version)
```

- `create` emits `signup.completed`, and refuses a taken email or username with `AUTH_EMAIL_TAKEN` or `AUTH_USERNAME_TAKEN`.
- Every write bumps `version`, a link included, so read the row again before an `updateProfile` that follows one.
- `updateProfile` merges the patch. A patch that changes `email` clears `emailVerified` in the same write, since a new address is unproven.
- `markEmailVerified(id, email)` sets the flag, and refuses once the identity no longer holds that address. `flows.completeEmailVerification` calls it for you.

## Provider links

```ts
await auth.identities.link(ada.id, { providerId: 'oauth:github', providerSub: '583231' }, session)
await auth.identities.unlink(ada.id, 'oauth:github', session)
```

Each takes the tenant last, `{}` by default, and links or unlinks only there. `link` refuses a provider the identity already holds in that tenant, and a login another identity holds there (`AUTH_PROVIDER_TAKEN`). `unlink` refuses to drop the last way in: the remaining links plus credentials such as a password must not reach zero. `flows.linkProvider` and `flows.unlinkProvider` wrap both for a signed-in user.

Both take the caller's `session`, `null` without one. Once the account has a factor beside the password in the link's tenant, each throws `AUTH_MFA_REQUIRED` unless that session is the account's own, [stepped up](/duck-auth/core/flows#step-up) to AAL 2 in that tenant and still fresh. An admin changing such an account writes through `auth.cfg.stores.identities`, which runs neither the step-up nor the last-way-in guard and emits no event.

## Deleting

| Call | Effect |
| --- | --- |
| `softDelete(id)` | Hides the row for the grace period (7 days by default, `identities.softDeleteGracePeriodMs`). |
| `restore(id)` | Clears a soft delete; after the window it throws `AUTH_GRACE_EXPIRED`. |
| `erase(id, { reason, operatorId })` | Removes the row and everything under it for good, and emits `identity.erased`. |
| `gc()` | Erases every row whose grace window has closed, and emits `identity.erased` with `reason: 'gc'` for each. Schedule it yourself. |

A soft delete does not end sessions; `flows.completeAccountDeletion` does both, and mails an undo link if asked.

## Bulk and export

```ts
const result = await auth.identities.bulkCreate(rows, { mode: 'skipExisting' })
// { created, skipped, failed }

const blob = await auth.identities.exportAll(ada.id, auth.cfg.stores.credentials, {}, { sessions: auth.cfg.stores.sessions })
// { identity, credentials, sessions, schemaVersion: '1', exportedAt }
```

`bulkCreate` matches existing rows by email: `skipExisting` passes over them, `merge` links the new logins onto them as `link` does with no session, so a row holding a factor beside the password gets none, and `replace` erases and recreates them, emitting `identity.erased` with `reason: 'bulkCreate replace'` for each row it erased. Its third argument is the tenant the logins it merges or creates are linked in. `exportAll` is the GDPR right-of-access export, with every credential secret and session CSRF hash removed. Its third argument is the tenant: `{}` exports the links, credentials and sessions with no tenant, `{ tenantId }` one tenant's, and `ALL_TENANTS` every tenant's.

`softDeleteMany`, `restoreMany`, `eraseMany`, `updateProfileMany`, `linkMany` and `unlinkMany` do the same over a set. `linkMany(links, session)` and `unlinkMany(links, session)` take one session for the whole set and answer only the rows it was allowed to change.
