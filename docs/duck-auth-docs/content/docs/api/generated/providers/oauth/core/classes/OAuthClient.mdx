### authedJson()

> **authedJson**(`url`: `string`, `accessToken`: `string`, `providerId?`: `string`): `Promise`\<`unknown`\>

Defined in: [packages/duck-auth/src/providers/oauth/core/client.ts:255](https://github.com/gentleeduck/duck-iam/blob/7b68e272765f6b233d7451837d0df2fdbddd0658/packages/duck-auth/src/providers/oauth/core/client.ts#L255)

An authenticated GET of a JSON endpoint, under the same 64KB cap as [OAuthClient.userinfo](#userinfo).
 For a provider whose profile needs a second call: GitHub keeps verified addresses on
 `/user/emails`, never on `/user`. The body is returned unnarrowed, because it is an array there
 and an object at userinfo.

### revoke()

> **revoke**(`token`: `string`, `opts?`: \{ `tokenTypeHint?`: `"refresh_token"` \| `"access_token"`; \}): `Promise`\<`void`\>

Defined in: [packages/duck-auth/src/providers/oauth/core/client.ts:192](https://github.com/gentleeduck/duck-iam/blob/7b68e272765f6b233d7451837d0df2fdbddd0658/packages/duck-auth/src/providers/oauth/core/client.ts#L192)

RFC 7009 token revocation, so disconnecting a provider or deleting an account can hand the upstream
 tokens back rather than leave them live at the IdP until they expire. Apple requires this call on
 account deletion. A token that was already invalid answers 200 by design, so only a transport failure
 or a non-2xx is a failure here.

#### Parameters

##### token

`string`

##### opts?

###### tokenTypeHint?

`"refresh_token"` \| `"access_token"`

#### Returns

`Promise`\<`void`\>
